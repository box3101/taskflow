# Smart Score v2 — 알고리즘 개선 설계

## 배경

v1의 구조적 문제 4가지를 해소한다.

1. **다중공선성** — 거래대금(20점)이 수급(40점)과 같은 축(외인+기관 거래금액)을 중복 측정
2. **절대 임계값** — 외인 매도 감점의 5000억 기준이 대형·중소형 간 불공평
3. **PER/PBR 계단 절벽** — 0.1 차이로 3점 격차, 적자·결측 처리 미정의
4. **등락률 곡선** — 추세 추종형이 매매원칙(장기 보유, 추격매수 지양)과 불일치

## 전체 구조

```
base = 수급(45) + 등락률(30) + 회전율(10) + PER/PBR(15)
       [거래대금 하위 20% 필터 통과 종목만]

# 밸류 부분 결측 시 재정규화 (섹션 4 참조)
normalized = 결측 보정 적용

# 과열감점은 재정규화 후 차감
종합 = normalized - 과열감점
```

## 데이터 스키마

SmartScore가 사용하는 실제 필드 (stockApi.ts 기준):

```typescript
// InvestorTrend — trends[] 배열의 각 요소
interface InvestorTrend {
  date: string
  foreign: number          // 외국인 순매수량
  institution: number      // 기관 순매수량
  individual: number       // 개인 순매수량
  foreignAmt: number       // 외국인 순매수금액 (백만원)
  institutionAmt: number   // 기관 순매수금액 (백만원)
}

// InvestorData — fetchInvestor() 반환값
interface InvestorData {
  trends: InvestorTrend[]   // 최근 거래일 순 (index 0 = 최근)
  per: string               // 문자열, parseFloat 필요
  pbr: string               // 문자열, parseFloat 필요
  marketCap: string         // 문자열 (백만원), parseFloat 필요
}

// StockQuote — themeQuotes에서 종목별
interface StockQuote {
  price: number
  changePct5: number        // 5일 등락률 (%)
  changePct20: number       // 20일 등락률 (%)
}
```

**주의**: `per`, `pbr`, `marketCap`은 문자열이므로 `parseFloat()` 후 `isNaN` 체크 필요.
`trends` 배열 길이는 API 응답에 따라 다름 (보통 5~20일). 10일 비율 계산 시 `.slice(0, 10)` 사용.

## 0. 거래대금 필터 (진입 전)

- 유니버스 내 5일 외인+기관 절대거래금액 합산 기준 하위 20% → 랭킹 제외
- 산식: `absAmt = trends.slice(0,5).reduce(|foreignAmt| + |institutionAmt|)`
- 점수가 아닌 필터: "사기 좋은 종목"이 아니라 "못 사는(슬리피지) 종목"이므로
- **튜닝 대상**: 커트라인 20% (데이터 분포 확인 후 조정)

---

## 1. 수급 45점

금액 우위(25) > 지속성(20). v1의 연속일 과대배점 + 노이즈 문제 해소.

### 지속성 20점 — 순매수일 비율 (스트릭 대체)

| 항목 | 산식 | 필드 | 최대 |
|------|------|------|------|
| 외인 순매수일 비율 | `(trends.slice(0,10) 중 foreign > 0인 일수 / 10) × 10` | `foreign` | 10점 |
| 기관 순매수일 비율 | `(trends.slice(0,10) 중 institution > 0인 일수 / 10) × 10` | `institution` | 10점 |

- "연속"이 아닌 "비율"로 노이즈 제거: 8/10일 매수 > 5일 연속 후 이탈
- 하루 매도 끼어도 점수가 급락하지 않음
- trends가 10일 미만이면 실제 길이를 분모로 사용

### 금액 25점 — 백분위 기반 (시총 대비)

| 항목 | 산식 | 필드 | 최대 |
|------|------|------|------|
| 외인 | 유니버스 내 (5일 순매수합 / marketCap) 백분위 × 12.5 | `foreignAmt`, `marketCap` | 12.5점 |
| 기관 | 유니버스 내 (5일 순매수합 / marketCap) 백분위 × 12.5 | `institutionAmt`, `marketCap` | 12.5점 |

- **백분위 기반**: 상수 튜닝 없이 첫 실행부터 분포가 자동으로 퍼짐
- 순매수합 = `trends.slice(0,5).reduce(sum, d => sum + Math.max(0, d.foreignAmt))` (음수는 0 처리)
- `min(12.5, ...)` 클램프 필수 (백분위 1.0 = 12.5점 상한)

### 외인 연속매도 감점

- 트리거: 연속매도 3일 이상 (기존 `consecutiveSellDays` 로직 유지)
- 강도: **시총 대비 매도금액 비율**에 비례 (v1의 5000억 절대값 폐기)
- 산식: `sellRatio = |5일 순매도합| / marketCap`, 임계 초과 시 감점 강화
- **튜닝 대상**: 임계값 0.5% (비율 비례 감점, 최대 -12점)

## 2. 등락률 30점 — 종 모양 곡선

추세 추종 → 눌림목·초기상승 포착으로 전환.

### 20일 등락률 (최대 22점) — `changePct20`

```
피크: +10% ~ +25% (만점 구간, 고원 형태)
좌측 감쇠: 0% 이하 → 저점수
우측 감쇠: +50% 이상 → 0점 수렴
```

구현 예시 (구간별 선형):
```
chg <= 0%  → 0점
0~10%      → 0 ~ 22 (선형 상승)
10~25%     → 22 (고원, 만점)
25~50%     → 22 ~ 0 (선형 하강)
50%+       → 0점
```

### 5일 등락률 (최대 8점) — `changePct5`

```
피크: +3% ~ +10% (만점 구간)
우측 감쇠: +25% 이상 → 0점 수렴
```

### 과열감점과의 관계

5일 +40%는 종모양에서 이미 0점 근처이나, 과열감점도 별도 적용한다.
**의도적 이중벌칙**: "지금 사면 안 된다"는 강한 배제 신호.

- **튜닝 대상**: 피크 폭(넓은 고원 권장), 감쇠 기울기

---

## 3. 회전율 10점 — surge 신호

거래대금 점수에서 분리된 독립 축. 수급(방향 있음)과 다른 "시장 관심 집중" 신호.

### 산식 — 2단 정규화

1. **surge 비율** = 5일 회전율 / 60일 회전율 → "평소 대비 몇 배 터졌나"
   - 회전율 = `(|foreignAmt| + |institutionAmt|) / marketCap` (해당 구간 평균)
   - 5일: `trends.slice(0, 5)`
   - 60일: 캐시 또는 가용한 trends 전체 (보통 20일이면 그걸 기준으로)
2. **유니버스 백분위** × 10 → 이상치(10배+ 튐) 안정화, 최대 10점

| 단계 | 목적 |
|------|------|
| surge 비율 | 평소 대비 관심 급증 포착 |
| 백분위 | 꼬리 분포 이상치가 만점 독식 방지 |

- 방향 무관: 매수·매도 구분 없이 절대거래금액 기반

### 데이터 제약

현재 `trends` 배열이 60일분을 제공하지 않을 수 있음.
가용 데이터가 20일 이하이면 60일 대신 가용 전체를 "장기 평균"으로 사용.
v2 이후 API 확장 시 60일로 전환.

## 4. PER/PBR 15점 — 선형 보간 + 지표별 독립 판정

계단 절벽 제거. 부드러운 감쇠 + 바닥 보장.

### PER (최대 8점) — `parseFloat(data.per)`

```
per_score = max(1, min(8, 8 - (PER - 5) * 0.28))
```

| PER | 점수 |
|-----|------|
| ≤5 | 8 |
| 10 | 6.6 |
| 15 | 5.2 |
| 20 | 3.8 |
| 25 | 2.4 |
| 30+ | 1 (바닥) |

### PBR (최대 7점) — `parseFloat(data.pbr)`

```
pbr_score = max(1, min(7, 7 - (PBR - 0.5) * k))
```

- **튜닝 대상**: 계수 k (1.5 제안, 미확정)
- k=1.5일 때: PBR 0.5→7, PBR 2→4.75, PBR 4→1.75, PBR 4.5+→1(바닥)

### 지표별 독립 판정 (적자 / 결측 / 정상)

PER과 PBR을 **각각 독립적으로** 판정한다.

| PER 상태 | PBR 상태 | 처리 |
|----------|----------|------|
| 정상 | 정상 | 둘 다 정상 계산, 밸류 = per_score + pbr_score (만점 15) |
| 적자 (음수) | 정상 | PER = 2점 고정, PBR = 정상 계산, 밸류 = 2 + pbr_score (만점 9) |
| 정상 | NaN | PER = 정상 계산, PBR 제외 → 밸류 만점을 8로 재조정, 나머지 92점→100점 재정규화 |
| NaN | 정상 | PBR = 정상 계산, PER 제외 → 밸류 만점을 7로 재조정, 나머지 92점→100점 재정규화 |
| 둘 다 NaN | — | 밸류 15점 전체 제외, 나머지 85점→100점 재정규화 |
| 적자 | NaN | PER = 2점 고정, PBR 제외, 밸류 만점 = 2+정상PBR범위 없으므로 → 수급+등락+회전+2점, 93점→100점 재정규화 |

- `console.warn`으로 결측 종목 로그 출력 (데이터 문제 가시화)
- PBR 음수는 자본잠식이 아닌 한 발생하지 않음 → 음수 PBR은 NaN과 동일 처리

### 재정규화 공식

```typescript
// 밸류 점수가 부분/전체 결측인 경우
const maxValuation = perAvailable ? 8 : 0 + pbrAvailable ? 7 : 0  // 실제 사용 가능한 밸류 만점
const baseMax = 85 + maxValuation  // 이론 만점
const base = supply + momentum + surge + valuation  // 감점 전 원점수
const normalized = base / baseMax * 100

// 과열감점은 재정규화 후 차감
const total = normalized - overheatPenalty
```

**과열감점은 정규화 대상이 아니라 정규화 후 차감이다.**

## 5. 과열 감점

| 조건 | 수급 동반(3일+ 순매수) | 수급 미동반 |
|------|----------------------|------------|
| 20일 >90% | -8 ~ -12 | -18 ~ -22 |
| 5일 >40% | -8 ~ -12 | -18 ~ -22 |

- 등락률 종모양과 이중벌칙 (의도적)
- 수급 동반 판정: 지속성 비율 기준 (10일 중 순매수 3일+)

| 등락률 피크 폭 | 넓은 고원 (10~25%) | 감쇠 기울기 포함 |
| PBR 계수 k | 1.5 | 데이터 분포 확인 후 |
| 매도감점 시총 대비 임계 | 0.5% | 비율 비례 감점 |
