# 상영 캘린더 개선 설계 스펙

- 작성일: 2026-07-21
- 대상 프로젝트: TaskFlow
- 선행 스펙: `2026-07-20-screening-calendar-design.md`
- 목표: 영화 상세 정보, 보고 싶은 영화 표시, 성인물 제외, 재개봉 표시를 기존 상영 캘린더에 추가

## 1. 배경

현재 상영 캘린더는 KOBIS에서 받은 개봉일·장르·감독·박스오피스 정보를 보여주지만 다음 한계가 있다.

- 영화 상세 화면에 줄거리와 포스터가 없다.
- 사용자가 보고 싶은 영화를 표시하거나 캘린더에서 구분할 수 없다.
- KOBIS 개봉작 목록에 포함된 성인물이 함께 노출된다.
- 재개봉작을 일반 개봉작과 구분할 수 없고, 일부 재개봉작은 캘린더에 나타나지 않을 수 있다.

이번 개선은 기존 KOBIS 기반 데이터 파이프라인을 유지하면서 TMDB를 보조 데이터 소스로 사용하고, 사용자별 북마크와 표시 규칙을 추가한다.

## 2. 확정된 결정

| 항목 | 결정 |
|------|------|
| 줄거리·포스터 소스 | TMDB API |
| TMDB 조회 방식 | 영화 상세 드로어를 처음 열 때 지연 조회 후 DB 캐시 |
| 포스터 표시 위치 | 영화 상세 드로어만 |
| 북마크 조작 위치 | 영화 상세 드로어 |
| 북마크 시각 표현 | 캘린더 배지를 노랑으로 표시 |
| 성인물 처리 | 동기화 단계에서 DB 저장 대상에서 제외하고 기존 데이터도 정리 |
| 재개봉 표시 | KOBIS 제작연도와 개봉연도 차이를 이용한 추정값 |

## 3. 전체 구조

```text
KOBIS API ──매일 동기화──▶ Movie
  ├ 개봉일·제작연도·장르 저장
  ├ 성인물 제외
  └ 재개봉 여부 계산

상세 드로어 ──GET /movies/:movieCd──▶ Movie에 TMDB 정보가 있는지 확인
  ├ 있음/이미 조회함: DB 데이터 반환
  └ 미조회: TMDB 검색 → 줄거리·포스터 경로 저장 → 반환

사용자 ──북마크 토글──▶ MovieBookmark
  └ 캘린더 조회와 별도로 내 북마크 코드 목록 조회 → 배지 색 결정
```

KOBIS는 영화 식별·개봉일·박스오피스의 기준 데이터로 유지한다. TMDB는 줄거리와 포스터만 보강하며, TMDB 장애가 KOBIS 동기화나 캘린더 목록 조회를 막지 않도록 분리한다.

## 4. 데이터 모델

### 4.1 `Movie` 확장

기존 `Movie` 모델에 다음 필드를 추가한다.

| 필드 | 타입 | 용도 |
|------|------|------|
| `productionYear` | `Int?` | KOBIS `prdtYear`; 재개봉 추정 기준 |
| `isRerelease` | `Boolean @default(false)` | 재개봉 추정 결과 |
| `tmdbId` | `Int?` | 매칭된 TMDB 영화 ID |
| `overview` | `String? @db.Text` | 한국어 줄거리 |
| `posterPath` | `String?` | TMDB 포스터 상대 경로 |
| `tmdbCheckedAt` | `DateTime?` | TMDB 조회 시도 시각; 실패 결과도 캐시 |

`tmdbCheckedAt`이 있으면 TMDB 매칭에 실패했더라도 상세 화면을 열 때마다 외부 API를 반복 호출하지 않는다. 잘못 매칭되거나 누락된 데이터를 다시 조회해야 할 때는 해당 영화의 TMDB 관련 필드와 `tmdbCheckedAt`을 관리 작업으로 초기화한다.

### 4.2 `MovieBookmark` 신규

| 필드 | 타입 | 용도 |
|------|------|------|
| `id` | `Int @id @default(autoincrement())` | 내부 식별자 |
| `userId` | `Int` | 북마크 소유 사용자 |
| `movieCd` | `String` | KOBIS 영화코드 |
| `createdAt` | `DateTime @default(now())` | 등록 시각 |

- `@@unique([userId, movieCd])`로 중복 등록을 막는다.
- `User`와 `Movie`에 관계를 연결하고, 사용자 또는 영화 삭제 시 북마크도 삭제한다.
- 북마크는 사용자별 데이터이며 모든 관련 API에 기존 `authenticate` 미들웨어를 적용한다.

## 5. 백엔드

### 5.1 TMDB 클라이언트

신규 파일 `backend/src/services/tmdb.ts`에 TMDB 호출과 응답 파싱을 격리한다.

- 환경변수: `TMDB_API_KEY`
- 검색 API: 영화명, 영문명, 개봉연도를 이용해 `language=ko-KR`로 검색
- 결과 선택 우선순위:
  1. 한글 제목 또는 영문 제목이 일치하는 후보
  2. KOBIS 개봉연도와 TMDB 개봉연도가 같은 후보
  3. 조건을 만족하는 후보가 하나일 때만 채택
- 모호하거나 결과가 없으면 임의의 첫 번째 영화를 저장하지 않고 매칭 실패로 처리한다.
- 저장 대상은 `tmdbId`, `overview`, `posterPath`이며 빈 한국어 줄거리는 `null`로 저장한다.

TMDB API 키가 없거나 호출이 실패하면 기존 KOBIS 상세 정보만 반환한다. 외부 API 오류 때문에 상세 API 전체가 500으로 실패해서는 안 된다. 네트워크 오류는 일시 오류이므로 `tmdbCheckedAt`을 기록하지 않고 다음 요청에서 재시도하고, 정상 응답이지만 매칭 결과가 없는 경우에만 조회 완료 시각을 기록한다.

### 5.2 상세 API 확장

`GET /movies/:movieCd` 처리:

1. DB에서 영화를 조회하고 없으면 404를 반환한다.
2. `tmdbCheckedAt`이 없고 `TMDB_API_KEY`가 있으면 TMDB 보강을 시도한다.
3. 성공 또는 정상적인 매칭 실패 결과를 DB에 저장한다.
4. 최신 `Movie` 데이터를 반환한다.

동시에 같은 영화를 열어 중복 TMDB 호출이 발생할 수 있으나 데이터는 동일한 행에 갱신되므로 기능상 충돌은 없다. 초기 버전에서는 별도 분산 락을 도입하지 않는다.

### 5.3 북마크 API

기존 `/movies` 라우터에 다음 엔드포인트를 추가한다.

- `GET /movies/bookmarks`
  - 로그인 사용자의 북마크된 `movieCd` 배열 반환
  - 캘린더 화면 진입 시 한 번 호출
- `POST /movies/:movieCd/bookmark`
  - 해당 영화가 존재하는지 확인 후 `upsert`
  - 이미 북마크되어 있어도 성공하는 멱등 동작
- `DELETE /movies/:movieCd/bookmark`
  - 로그인 사용자와 영화코드 조합을 삭제
  - 이미 없어도 성공하는 멱등 동작

정적 경로 `/bookmarks`는 `/:movieCd`보다 먼저 선언해 파라미터 라우트와 충돌하지 않도록 한다.

### 5.4 성인물 제외

KOBIS 영화목록 동기화에서 장르 문자열을 정규화한 뒤 `성인물` 또는 `에로`가 포함된 영화는 upsert하지 않는다. 영화목록 동기화가 끝난 후 기존 `Movie` 중 같은 조건에 해당하는 행을 삭제한다.

- 삭제는 매 동기화에서 실행해 결과를 멱등하게 유지한다.
- 연결된 북마크가 있다면 관계의 `onDelete: Cascade`에 따라 함께 삭제한다.
- 월별 영화 API와 현재상영작 API에도 같은 장르 조건을 방어적으로 적용하여, 박스오피스 단계에서 메타데이터가 아직 채워지지 않은 경우를 제외하고 성인물이 응답되지 않게 한다.
- 장르가 아직 없는 영화는 오탐 방지를 위해 자동으로 성인물로 간주하지 않는다.

### 5.5 재개봉 판정

KOBIS 영화목록의 `prdtYear`를 숫자로 저장하고 다음 조건으로 재개봉을 추정한다.

```text
isRerelease = productionYear가 존재하고
              openDt가 존재하고
              openDt 연도 - productionYear >= 2
```

이 값은 KOBIS가 명시적으로 제공하는 재개봉 플래그가 아니라 휴리스틱이다. 제작 후 2년 이상 지나 처음 개봉한 영화도 재개봉으로 표시될 수 있다.

또한 KOBIS가 재개봉일 대신 원개봉일을 `openDt`로 반환하면 해당 영화는 현재 월 캘린더에 배치할 수 없다. 구현 검증 시 최근 재개봉작을 실제 KOBIS 응답과 대조하고, 이 경우 현재상영작 목록에는 나타날 수 있어도 월간 캘린더 노출은 보장하지 않는다.

## 6. 프론트엔드

### 6.1 상세 드로어

`MovieDetailDrawer.vue`를 다음과 같이 확장한다.

- 드로어가 열릴 때 상세 API를 호출해 TMDB 보강 결과를 받는다.
- `posterPath`가 있으면 상단에 `https://image.tmdb.org/t/p/w342{posterPath}` 이미지를 표시한다.
- `overview`가 있으면 별도 "줄거리" 섹션을 표시한다.
- 데이터가 없으면 포스터 자리나 빈 줄거리 문구를 만들지 않고 기존 텍스트 상세만 표시한다.
- 이미지 로딩 실패 시 깨진 이미지 아이콘을 숨긴다.
- 상단에 ispark-ui 버튼/아이콘을 사용한 "보고싶어요" 토글을 배치한다.
- `isRerelease`가 참이면 개봉 상태 배지 옆에 "재개봉" 배지를 표시한다.

상세 로딩 중에는 드로어 자체를 닫지 않고 내용 영역에 로딩 상태를 표시한다. TMDB 보강 실패 시 토스트로 외부 연동 실패를 과도하게 노출하지 않고, 기존 상세 정보로 정상 표시한다.

### 6.2 북마크 상태와 동기화

`ScreeningCalendarView.vue`가 화면 진입 시 내 북마크 영화코드 목록을 `Set<string>` 형태로 보관한다.

- 드로어에 현재 영화의 북마크 여부를 전달한다.
- 드로어에서 토글 성공 이벤트가 오면 같은 `Set`을 새 객체로 교체해 반응성을 보장한다.
- `monthMovies`, `nowShowing`, `selectedMovie`가 같은 영화 정보를 참조하므로, 상세 API로 보강된 영화 객체를 받으면 세 상태를 모두 동일한 최신 객체로 동기화한다.
- API 실패 시 낙관적 상태를 확정하지 않고 기존 북마크 상태를 유지하며 오류 토스트를 표시한다.

### 6.3 캘린더와 목록 표시

캘린더 배지 색 우선순위:

1. 북마크됨: 노랑 `#f59e0b`
2. 북마크 아님 + 미래 개봉: 파랑 `#3b82f6`
3. 북마크 아님 + 개봉일이 오늘 이하: 초록 `#22c55e`

범례에 "보고싶은 영화"를 추가한다. 재개봉작의 캘린더 제목에는 `[재개봉]` 접두어를 붙이고, 선택 날짜 목록과 현재상영작 목록에는 별도 작은 "재개봉" 배지를 표시한다.

## 7. 오류 처리와 보안

- `TMDB_API_KEY`는 백엔드 환경변수에만 두며 프론트 번들에 포함하지 않는다.
- TMDB 장애·요청 제한·키 미설정 시 KOBIS 데이터만 반환한다.
- TMDB 검색 문자열과 응답값은 DB 쿼리에 직접 조합하지 않고 API 파라미터 및 Prisma 입력으로 전달한다.
- 포스터는 TMDB가 반환한 상대 경로만 저장하며 임의 외부 URL을 렌더링하지 않는다.
- 북마크 API는 인증 사용자 ID만 사용하고 요청 본문의 사용자 ID를 신뢰하지 않는다.
- 영화가 없으면 북마크 생성은 404, 상세 조회도 404를 반환한다.

## 8. 테스트 및 검증

### 백엔드

- TMDB 검색 후보가 제목과 연도로 정확히 매칭되는지 테스트
- 모호한 후보, 결과 없음, 네트워크 오류를 각각 구분하는지 테스트
- 정상 매칭 실패는 재호출하지 않고 네트워크 실패는 재시도 가능한지 테스트
- 북마크 생성·중복 생성·삭제·중복 삭제 및 사용자 간 분리 테스트
- `성인물(에로)` 등 장르 문자열이 저장·응답에서 제외되는지 테스트
- 제작연도와 개봉연도 차이에 따른 재개봉 판정 경계값 테스트
- 기존 영화 월별 조회와 현재상영작 조회가 계속 동작하는지 회귀 테스트

### 프론트엔드

- 북마크 배지 색이 개봉 상태 색보다 우선하는지 테스트
- 북마크 토글 후 캘린더와 드로어 상태가 함께 갱신되는지 테스트
- 상세 API 응답으로 월별 목록·현재상영작·선택 영화 참조가 동기화되는지 테스트
- 포스터·줄거리 없음 및 이미지 로딩 실패 상태 테스트
- 재개봉 접두어와 배지가 조건에 따라 표시되는지 테스트

### 실제 데이터 검증

- 일반 개봉작 한 편: TMDB 줄거리와 포스터 매칭
- 동명 영화: 잘못된 TMDB 영화가 선택되지 않는지 확인
- 최근 재개봉작 한 편: KOBIS `prdtYear`, `openDt`, 캘린더 노출 여부 확인
- KOBIS 장르가 성인물인 영화: DB와 API에서 제외 확인

## 9. 구현 마일스톤

### M1 — 스키마·동기화 규칙

- `Movie` 필드와 `MovieBookmark` 모델 추가
- Prisma DB 반영 및 클라이언트 생성
- KOBIS `prdtYear` 파싱, 재개봉 판정, 성인물 제외/정리
- 실제 데이터로 성인물과 재개봉 사례 검증

### M2 — TMDB·북마크 API

- TMDB 클라이언트와 매칭 로직
- 영화 상세 API의 지연 보강
- 북마크 조회·추가·삭제 API
- 백엔드 단위/라우트 테스트

### M3 — 화면

- 상세 드로어의 포스터·줄거리·북마크·재개봉 표시
- 캘린더 북마크 색과 범례
- 목록의 재개봉 배지
- 객체 참조 및 캐시 동기화
- 반응형 화면과 다크 모드 확인

각 마일스톤 완료 후 해당 범위의 검증을 통과한 뒤 다음 마일스톤으로 진행한다.

## 10. 사전 준비

- TMDB 계정과 API 키 발급
- 백엔드 `.env`에 `TMDB_API_KEY` 설정
- 개발·배포 환경 모두 같은 변수 이름을 사용하되 키 값은 저장소에 커밋하지 않는다.

## 11. 범위 밖

- 북마크 전용 별도 페이지
- 북마크 메모·별점·관람 완료 상태
- TMDB 데이터 전체 사전 동기화
- 배우 목록, 예고편, 상영시간표
- 관리 화면을 통한 TMDB 수동 매칭
- 사용자가 성인물 표시 여부를 바꾸는 토글
