# Superpowers 사용 가이드 (Cursor / Claude Code 공용)

> **핵심 한 줄** — 코드부터 시키지 말고, 계획 먼저 세우고 사람이 검토한다.

## 이게 뭔가요?

**Superpowers** — 새 기능을 바로 코딩하지 않고, "먼저 대화로 요구사항을 정하고 → 계획 문서를 만들고 → 그 다음 구현"하는 흐름을 잡아주는 도구입니다.

**brainstorming** — 그 첫 단계. AI가 "데이터는 어디서 오나요?", "클릭하면 뭐가 뜨나요?" 같은 질문을 하나씩 던지고, 답을 고르다 보면 요구사항이 저절로 정리됩니다.

**왜 쓰나** — "이거 만들어줘" 한 마디로 시작하면 AI가 혼자 가정을 세우고 엉뚱하게 만들기 쉽습니다. 그래서 코드보다 계획을 먼저, 사람이 검토하는 겁니다.

## 설치 (한 번만)

**Cursor** — Agent 채팅(Cmd/Ctrl+L)에 입력:

```
/add-plugin superpowers
```

**Claude Code** — 아래 두 줄:

```
/plugin marketplace add obra/superpowers-marketplace
/plugin install superpowers@superpowers-marketplace
```

설치되면 바로 활성화됩니다. 추가 설정(config·API키) 없음.

## 어떻게 부르나

특별한 명령어 없이 그냥 자연어로 말하면 됩니다.

```
상영 캘린더 기능을 brainstorming으로 잡아줘
```

`brainstorming`이라는 단어만 넣으면 AI가 알아서 스킬을 찾아 씁니다. (예전 `/명령어` 방식은 이제 안 써도 됨)

## 진행 흐름 (6단계)

| 단계 | AI가 하는 일 | 내가 할 일 |
|------|-------------|-----------|
| 1. 파악 | 프로젝트 파일·문서·커밋 훑어봄 | 기다리기 |
| 2. 질문 | 한 번에 하나씩, 객관식으로 물어봄 | 선택지 중 답하기 |
| 3. 제안 | 2~3가지 방법 + 장단점 + 추천안 제시 | 마음에 드는 것 고르기 |
| 4. 설계 | 섹션별로 설계안 보여줌 | 승인하거나 수정 요청 |
| 5. 저장 | 스펙 문서를 docs 폴더에 저장 | **저장된 스펙 직접 읽기** ★ |
| 6. 전환 | 구현 계획 짜기로 넘어감 | 계획도 읽고 확인 |

## 스펙이 어디 저장되나

`docs/superpowers/specs/` 폴더에 `YYYY-MM-DD-<주제>-design.md` 형태로 저장됩니다. 나중에 이 파일만 열어봐도 "뭘 만들기로 했는지" 다시 확인 가능합니다. 구현 계획은 `docs/superpowers/plans/`에 쌓입니다.

## 3단계 흐름

1. **brainstorm** — "만들어줘" ❌ → "brainstorm 해줘 + 질문해줘" ⭕
2. **계획 검토** — 스펙 직접 읽고 수정 ← ★개입 지점★
3. **실행** — 대화 비우고(Cursor: 새 채팅 / Claude Code: `/clear`) 마일스톤별로

## 실행은 2가지 (초보자는 왼쪽만)

계획이 나오면 구현 방식이 두 가지입니다. 처음엔 **일반 실행**만 쓰면 됩니다.

| | 일반 실행 (기본) | 서브에이전트 (고급) |
|--|-----------------|--------------------|
| 누가 하나 | 지금 이 AI가 쭉 | 작업마다 새 AI 투입 |
| 기억 | 앞 작업 계속 기억 | 작업마다 초기화 |
| 검증 | 없음 | 작업마다 리뷰 AI가 검사 |
| 속도 | 빠름 | 느림 |
| 언제 | 작업이 서로 연결됨 / 대부분 | 작업이 독립적 / 크고 품질 중요 |

> **처음엔 서브에이전트 신경 X** — 설정도 복잡하고 느립니다. 익숙해진 뒤, 크고 독립적인 작업에서만 쓰세요. 웬만하면 일반 실행으로 충분합니다.

## 꼭 기억할 5가지

1. **"질문해줘"를 넣는다** — AI가 혼자 가정 안 하게
2. AI가 물으면 **선택지 중에 고르며** 요구사항 확정
3. **스펙은 반드시 직접 읽는다** — 여기서 방향 잡음
4. **실행 전 대화 잡음 제거** (새 채팅 / `/clear`)
5. **마일스톤으로 쪼개서** 한 단계씩 확인

> 계획이 좋으면 실행은 알아서 굴러간다.

## 부록: brainstorming 스킬 상세

**개요** — 아이디어를 구체적인 설계 스펙으로 발전시킨다. 한 번에 하나씩 질문하며 요구사항을 구체화한 후, 2~3가지 접근법을 제안하고 승인된 디자인을 스펙 문서로 저장.

**사용법**

```
/superpowers:brainstorming [아이디어 설명]
```

**프로세스**

1. 프로젝트 컨텍스트 파악 — 파일, 문서, 커밋 확인
2. 명확화 질문 — 한 번에 하나씩, 가급적 객관식
3. 2~3가지 접근법 제안 — 트레이드오프 + 추천안
4. 디자인 섹션별 제시 — 승인 후 다음 섹션
5. 스펙 문서 저장 — `docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md`
6. writing-plans로 전환 — 구현 계획 작성

**핵심 원칙**

- 한 번에 하나의 질문 — 여러 질문 금지
- 객관식 선호 — 선택지 제공
- YAGNI — 불필요한 기능 제거
- **디자인 승인 전 코드 작성 절대 금지**
